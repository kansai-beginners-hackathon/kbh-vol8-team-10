# 受け入れ検証のやり直し方

`docs/受け入れ検証.md` の数字を出し直したいとき用のメモ。

## アプリ側の値（解散時刻）

`scripts/plan-cli.ts` が `components/Planner.tsx` と同じ呼び出し（`buildStations` → `rankVenues`）をします。ブラウザを開かずに順位と解散時刻が出るので、組み合わせを大量に試すときはこちらが速いです。

```bash
node scripts/plan-cli.ts "<メンバー>" "<候補地ID>" "<ダイヤ>" "<徒歩分>"
```

| 引数 | 書き方 | 例 |
|---|---|---|
| メンバー | `名前:駅` をカンマ区切り。名前を省くと駅名が名前 | `"田中:鞍馬,佐藤:桂"` / `"鞍馬,桂"` |
| 候補地ID | `data/network.ts` の `VENUES[].id` をカンマ区切り。`all` で 8 か所全部 | `"shijo,kyoto"` / `all` |
| ダイヤ | `weekday` または `weekend` | `weekday` |
| 徒歩分 | 店から駅までの分。Yahoo! と比べるときは `0` | `0` |

```bash
# 例: 鞍馬の人ひとり、全候補地、平日、徒歩0分
node scripts/plan-cli.ts "鞍馬" all weekday 0
```

出力は画面の並びと同じ（いられる時間の長い順）です。`対応予定: ...` の行が出たら、その駅は 7 ハブ全部で解けなかった人です。

> `next dev` は要りません。Transit API には実際に問い合わせるのでネットワークは要ります。

## 実測側の値（Yahoo!乗換案内）

https://transit.yahoo.co.jp/ で

- 出発 = 候補地、到着 = 自宅駅
- 日時 = **終電**、日付は 平日 2026/08/31（月） / 土休日 2026/08/30（日）
- 出てきたルートのうち **出発時刻が一番遅いもの**の出発時刻を読む

URL で直接叩く場合は `type=2` が終電検索です（`type=1` 出発 / `type=3` 始発 / `type=4` 到着）。

```
https://transit.yahoo.co.jp/search/result?from=<出発>&to=<到着>&type=2&ym=202608&d=31&hh=23&m1=0&m2=0
```

結果は 6 件を 3 件ずつの 2 ページで返します。**2 ページ目（`&fl=4&tl=6`）まで見ないと一番遅い便を取りこぼす**ことがあります。

### 駅名の注意

- `桂(京都府)` は駅として認識されず愛知県の住所になる。**`桂` と入れる**
- `四条(京都府)` → `四条(京都市営)` に解決される（正しい）
- `嵐山` は **`嵐山(阪急線)`** に解決される。嵐電の嵐山で比べたいときは駅を指定し直す
