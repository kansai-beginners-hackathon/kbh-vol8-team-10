### 2. アプリが実測より遅い時刻を出すケースが 79 組中 27 組（うち −10 分以上が 8 組）

要件定義の「アプリの方が遅い時刻を出したら即バグ」に該当します。原因は 2 つに切り分けました（`docs/受け入れ検証.md` の「✗ の原因」）。

- **原因 A（本質的）**: `lib/calc.ts` が候補地 → ハブを「いつ出ても `transitMin` 分」として扱っていて、その区間の**実際の発車時刻を見ていない**。深夜は 15〜20 分に 1 本なので、アプリの答えが「電車と電車の間」に落ちる。例: 出町柳 → 桂 はアプリ 23:52 だが実際に乗れる最終は 23:42
- **原因 B（すぐ効く）**: `data/hubs.ts` の `transferMin` が短い。烏丸御池 = 3 分は東西線 ↔ 烏丸線の階移動に対して短く、Yahoo! は成立しないと判定する。例: 三条 → 国際会館 でアプリ 23:41 / 実測 23:22（差 −19 分）。**烏丸御池・四条・京都河原町 を 3 → 5 分にすると、この系統はかなり減るはず**です

**B だけなら 1 行 × 3 なので発表前でも入ります。A は設計の話なので当日は無理だと思います。**

### 3. 24 時台の表示が `00:09` になる

`lib/time.ts` の `toStr` が `% 24` するので、解散が 24 時台のとき `00:09` と出ます。計算は正しいですが「深夜 0 時すぎ」と伝わりにくいです。

### 4. 「京都駅が最下位」は作れなかった

6006 通り × 2 セットを総当たりして 0 件でした。台本を書き換える必要があります。代わりに **「出町柳が 1 位にも最下位にもなる」**（1 位 2288 回 / 最下位 3536 回）が使えます。詳しくは `docs/デモ組み合わせ.md`。
